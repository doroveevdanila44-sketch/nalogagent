# Агент (вкладка чата)

## Принципы

1. Модель не считает. Числа приходят только из калькулятора (`lib/calc`).
2. Модель вызывается только для вопросов по теме. Этикет, служебное, вне темы и «за границей продукта» обслуживаются заготовками без токенов.
3. При сомнении агент переспрашивает, а не отказывает. Отказ на рабочий вопрос воспринимается как поломка.
4. Провайдер модели сменный. Весь доступ к модели через один интерфейс.
5. Понимание вопроса отделено от расчёта. Модель (позже) только извлекает поля: юрлицо, налог, период, сценарий. Что считать, что переспросить и чего не поддерживать, решает код, а число считает `calcTax`.
6. Агент показывает, как понял вопрос, перед результатом. Допущения (налог не назван, юрлицо не названо) видны и меняются одним нажатием.

## Интерфейс провайдера

```ts
// lib/agent/provider.ts
export interface LlmProvider {
  // вопрос в параметры прежних разделов (сценарий покупки машин)
  parse(question: string, ctx: ParseContext): Promise<ParsedIntent>;
  // готовое число в слова
  explain(result: CalcResult, question: string): Promise<string>;
  // поля вопроса: юрлица, налог, период, сценарий (необязательный метод)
  extract?(question: string, ctx: InterpretContext): Promise<Partial<RawFields>>;
}
```

`extract` возвращает «сырые» поля (`RawFields`). Всё, что вернул провайдер, проходит `sanitizeFields`: неизвестные юрлица, налоги, невозможные периоды и ставки отбрасываются. Без `extract` работают правила заглушки (`extractFields`).

Реализации выбираются переменной `LLM_PROVIDER`:

| Значение | Что это |
|---|---|
| `stub` | Правила и регулярные выражения, как в `reference/demo.html` (функция `reply`). По умолчанию в демо |
| `gigachat` | GigaChat API, включается после договора на ИП |
| `yandexgpt` | Резерв |

Для GigaChat: получение токена по идентификатору и секрету, токен живёт 30 минут, обновлять по расписанию. Корневые сертификаты НУЦ Минцифры установить на сервер. Ограничение расхода токенов и оповещение обязательны. Ключи только в окружении.

## Конвейер ответа

```
вопрос -> маршрутизатор -> класс
  A (по теме): поля вопроса -> понимание -> одно из:
       пояснение (не поддерживается)
       уточнение (не хватает налога или периода)
       расчёт calcTax -> explain -> предохранитель -> ответ с карточкой «Понял так»
       прежний раздел (ставки, пороги, вычет, дробление, покупка машин)
  B, C, D, E, F: заготовка
```

**Предохранитель.** Перед отправкой все числа в тексте ответа сверяются с набором чисел из результата расчёта (с учётом форматирования: «1,35 млн», «1 352 381 ₽»). Если в тексте есть число, которого нет в расчёте, ответ не уходит, в чат идёт заготовка «Не могу подтвердить расчёт, попробуйте переформулировать», запись попадает в журнал как сбой.

**Проверка полноты.** Не хватает налога или периода, которые нужны для расчёта: задать один уточняющий вопрос (раздел «Уточнения»). Юрлицо не названо: считать по группе и сказать об этом.

## Понимание вопроса

Модули `lib/agent/interpret.ts` (разбор), `entities.ts` (юрлица), `clarify.ts` (уточнения), `unsupported.ts` (пояснения), `tax-answer.ts` (ответ из `calcTax`).

`interpret(text, context)` возвращает `Interpretation`:

| Поле | Значение |
|---|---|
| `entities`, `entityMode` | id юрлиц группы; `named` названо, `group` («все», «группа»), `none` не названо |
| `tax` | `vat`, `usn`, `profit` или `null` |
| `period` | `Period` из `lib/calc`: месяц, квартал, год, с начала года, диапазон |
| `scenario` | `rate` (ставка), `compare_rates` (сравнение ставок), `forecast` (прогноз), `threshold` (порог), `payment` (ближайший платёж), прежние разделы `deduct`, `fragmentation`, `cars`; `null` это обычный вопрос про сумму |
| `rate` | ставка НДС 5, 7 или 22, если названа («по ставке 22%») |
| `confidence` | 0..1, растёт с названными юрлицом, налогом, периодом и сценарием |
| `ambiguities` | `missing` не хватает, `multiple` названо несколько, `assumed` взято по умолчанию |
| `unsupported` | что агент не берётся делать (раздел «Пояснения») |

Разбор правилами (заглушка), примеры:

| Фраза | Понято |
|---|---|
| «расчёт за февраль», «в феврале», «февральский» | месяц; год из «сегодня» |
| «за 1 квартал», «за 3 квартал 2026», «II кв.», «первый квартал» | квартал |
| «за 2025 год», «в 2026 году», «за год» | год |
| «с начала года» | накопление до сегодняшнего дня |
| «за прошлый месяц», «в этом квартале», «за прошлый год» | от «сегодня» |
| «за октябрь-декабрь», «с марта по май», «с 1 по 15 октября» | диапазон |
| «за полугодие», «за 9 месяцев» | с января |
| «по Бете за август», «НДС Альфа 2 квартал» | юрлицо, налог, период в любом порядке |
| «по Альфе и Бете», «все», «группа» | несколько юрлиц, вся группа |
| «налог по упрощёнке», «налог на прибыль», «НДС» | налог |

Допущения (видны в карточке, меняются кнопкой «Изменить»):

- налог не назван, период назван: считается НДС;
- юрлицо не названо: считается по группе, в ответе так и сказано;
- «за квартал», «за месяц» без номера: текущий квартал или месяц.

Год без периода не подставляется: годовой прогноз показывается только на вопрос про год.

**Склейка с прежним вопросом.** Короткий ответ («февраль», «УСН», «по Бете», «а за март?») продолжает прежний вопрос: недостающие поля берутся из понимания предыдущего ответа, оно хранится в сообщении агента (`chat_messages.calc.interp`). Не склеиваются: целый вопрос (названы и налог, и период) и вопрос со своим сценарием («что с порогами?»). Кнопка под ответом передаёт номер ответа (`baseId` в `POST /api/chat`) и продолжает именно его, даже если после него были другие сообщения.

## Ответ по существу

Сумма налога за период берётся только из `calcTax` для понятого периода: за февраль выдаётся февраль (по юрлицам, итог, ближайший платёж), за квартал квартал, за год годовой прогноз.

| Налог в вопросе | Что показано |
|---|---|
| `vat` | НДС по юрлицам: выручка, налог, ставка; помесячно для периода от двух до шести месяцев; ближайший платёж по графику |
| `usn` | налог по УСН у юрлиц на упрощёнке; юрлицо на ОСНО показывается с налогом на прибыль и пояснением |
| `profit` | налог на прибыль и налог по УСН (как блок «Налог на прибыль и УСН» на дашборде): у юрлиц на УСН налога на прибыль нет, для них показан налог по УСН |

На вопрос «сколько НДС за 2025 год» без правил на год ответ честный: выручка есть, налог не рассчитан, нет правил на этот год. Формулы, шаги и правила в «Как посчитано» те же, что у `calcTax` (см. `CALC.md`).

## Карточка «Понял так»

Первая строка ответа: «Понял так: ООО «Альфа», НДС, февраль 2026 (факт)». Три значения: юрлицо, налог, период. Пометка по данным периода: «факт», «прогноз» или «факт и прогноз» (идущий месяц делает период смешанным). Под ней допущения, если они были. Кнопка «Изменить» раскрывает варианты (юрлицо, налог, период); выбор уходит в чат как короткий ответ и пересчитывает прежний вопрос.

Карточка есть у ответов с налогом и периодом (сумма, ставки, пороги, сценарий покупки). У пояснений, вычета и признаков дробления её нет.

## Уточнения

Если не хватает налога или периода, агент задаёт один короткий вопрос с кнопками:

| Чего нет | Вопрос | Кнопки |
|---|---|---|
| налога и периода | «Какой налог и за какой период посчитать?» | НДС, УСН, Налог на прибыль; с начала года, текущий месяц, последний завершённый квартал, текущий год |
| периода | «За какой период посчитать налог на прибыль?» | периоды |
| налога у ближайшего платежа | «Какой налог?» | налоги |
| названо несколько налогов или несколько отдельных периодов | «Какой налог посчитать: …?», «Какой период посчитать?» | названные варианты |

Подписи кнопок считаются от «сегодня». Ответ на уточнение не требует повторять вопрос.

## Пояснения вместо общего отказа

В каждом ответе последняя строка «Что могу сейчас» с двумя-тремя примерами вопросов. В пояснениях нет чисел, кроме годов из вопроса и границ данных.

| Случай | Что говорит агент |
|---|---|
| период до 2025 или после 2026 | «Данные в демо с января 2025 по декабрь 2026, за … посчитать не могу». Границы берутся из `revenue_monthly` |
| 2027 год | «Лимиты 2027 пока не утверждены, жду дефлятор» и границы данных |
| налог не из списка (НДФЛ, страховые взносы, ЕНВД, патент, налог на имущество) | какой налог не считается, что считается (НДС, УСН, налог на прибыль) |
| юрлицо не из группы | название и список юрлиц группы |
| юридическая оценка схем | отказ из набора по кругу (общий счётчик с вопросами вне темы) и строка «Что могу сейчас» |
| как раздробить, как обойти | заготовка границы продукта, как раньше (класс F) |

## Маршрутизатор

Без модели, по порядку:

1. Точные совпадения: приветствия, благодарности, прощания, `/start`, `/help`.
2. Словарь темы: НДС, ставка, порог, вычет, выручка, декларация, квартал, упрощёнка, дробление, юрлицо, имена юрлиц группы. Одно попадание: класс A.
3. Запросы о схемах обхода («раздробить, чтобы не заметили»): класс F.
4. Явно не по теме (погода, стихи, анекдоты, рецепты, футбол): класс D.
5. Иначе класс E, уточняющий вопрос.

Добавлено к порядку выше:

- Оценка схемы с точки зрения закона («законно ли», «легально ли», «признает ли налоговая») идёт в класс A: понимание отвечает отказом из набора по кругу. «Как раздробить» остаётся классом F.
- В словарь темы входят «расчёт», «посчитай», «начислено» и налоги вне списка (НДФЛ, взносы, ЕНВД, патент): агент объяснит, что их не считает.
- Короткий ответ на уточнение или поправка к прежнему вопросу («февраль», «УСН», «по Бете») идёт в класс A, если есть вопрос, на который он отвечает. Без прежнего вопроса «февраль» остаётся непонятным (класс E).

Позже добавить второй контур на эмбеддингах (российский провайдер), пока не нужен.

## Заготовки

**Приветствие** (по времени суток клиента, Камчатка UTC+12): «Здравствуйте. Чем помочь по налогам?» / «Доброе утро. Готов считать.» / «Добрый день. Что посчитать?» / «Добрый вечер. Слушаю ваш вопрос.»

**Благодарность:** «Пожалуйста.» / «Рад помочь.» / «Обращайтесь.» / «Всегда пожалуйста. Понадобится пересчитать, скажите.»

**Прощание:** «До свидания. Хорошего дня.» / «Всего доброго.» / «До связи, я на месте.»

**Уточнение:** «Уточните, пожалуйста: по какому юрлицу и за какой период?» / «Переспрошу, чтобы не ошибиться: что именно посчитать?»

**Граница продукта:** «Такие схемы я не проектирую. Но могу показать, какие признаки дробления видны в ваших данных и во сколько может обойтись риск.»

**Что умеешь:** выбор ставки 5, 7 или 22 процента, пороги, прогноз квартала и сроки платежей, сценарии вроде покупки машин.

**Десять формулировок отказа** (по кругу, индекс последней использованной хранится по пользователю в базе, следующая берётся по порядку, не случайно):

1. Это не моя тема. Я считаю налоги по вашей группе компаний: НДС, ставки, пороги. Спросите про них, и я отвечу.
2. Тут я не помощник, извините. Моя работа это налоговые расчёты, всё остальное мимо меня.
3. Не возьмусь: это за пределами того, что я умею. Зато считаю НДС и слежу за порогами.
4. В этом я не разбираюсь. А вот в налогах на упрощёнке разбираюсь хорошо, спрашивайте.
5. Такое я не считаю. Могу посчитать налоговую нагрузку, выбор ставки или прогноз на квартал.
6. Это не ко мне. Я отвечаю только по налогам ваших юрлиц, с остальным лучше к человеку.
7. Скажу честно: не моя область. Вернёмся к налогам, там от меня есть польза.
8. Я про налоги, а это уже другая история. Задайте вопрос по НДС или по выручке, посчитаю.
9. Здесь ничем не помогу. Моё дело расчёт НДС и контроль сроков, обращайтесь по ним.
10. Не мой профиль. Если нужен расчёт по ставке, порогу или сроку, я готов.

## Правила тона

- Здороваться один раз за сессию, сессия заканчивается после четырёх часов молчания.
- Не извиняться дважды в одном ответе и не извиняться за отказ вне темы.
- Не предлагать того, чего система не умеет.
- На «вы», без имени в каждом сообщении.
- Ответ с расчётом не длиннее шести строк, полный разбор в раскрывающемся блоке «Как посчитано».
- Не шутить про налоговую, проверки и штрафы.
- Числа только из калькулятора.

## Интенты, которые уже есть в прототипе (перенести)

Ставки (таблица по трём ставкам и лучшая), предупреждения о порогах, признаки дробления, прогноз квартала со сроками платежей (три равные части до 28 числа месяцев после квартала), вычет входного НДС, сценарий покупки машин (пересчёт доли закупок p и налога по 22%), граница продукта. Логика в `reference/demo.html`, функции `aRates`, `aWarn`, `aFrag`, `aForecast`, `aDeduct`, `aProfit`, `aScenario`, `reply`. Перенесено как заготовки текста с подстановкой чисел из `lib/calc`, расчёты из прототипа не копировались. Налог на прибыль и УСН считаются (`calcTax`), налог за период отвечает разделом «Ответ по существу».

## Интерфейс чата

- Сообщения: пользователь справа (тёмный оливковый `#2A2B14`, текст белый), агент слева (светлая плашка), над ответом карточка «Понял так» с кнопкой «Изменить», под ответом подпись «Цифры из калькулятора» и раскрывающийся блок «Как посчитано» с формулами, ниже кнопки быстрых ответов (уточнение, сужение до юрлица).
- Подсказки-кнопки над полем ввода: короткие готовые вопросы («Какая ставка выгоднее?», «Сколько платить за квартал?», «Что с порогами?»).
- Поле ввода: высота 38 px, радиус 12, кнопка «Отправить» 38 px. Закреплено над нижней панелью, с учётом `safe-area-inset-bottom`.
- История хранится в базе (`chat_messages`), при заходе подгружаются последние 50.
- Индикатор набора, пока идёт ответ. Отправка по Enter, перенос по Shift+Enter.

## Журнал

Каждый вопрос и ответ пишутся в `chat_messages`, расход токенов и время ответа в `llm_usage`. Пароли и PIN в журнал не попадают никогда (см. `AUTH.md`).

## Тесты

1. На 100 фразах (40 по теме, 30 этикет, 30 вне темы) не больше 5 ошибок классификации.
2. Десять отказов идут по кругу и не повторяются подряд.
3. Предохранитель: подставить в ответ модели чужое число, ответ не уходит.
4. На 30 контрольных вопросах ни в одном ответе нет числа вне расчёта.
5. Заглушка и GigaChat проходят один и тот же набор тестов через общий интерфейс.
6. Понимание: не меньше 30 формулировок в таблице (`interpret.test.ts`): юрлица, налоги, периоды, сценарии, неподдерживаемое.
7. «Расчёт за февраль» даёт февральские цифры, а не годовые; «НДС Альфа 2 квартал» даёт II квартал; неоднозначное «сколько платить» вызывает уточнение; «налог за 2027» даёт пояснение; ответ «февраль» после вопроса про НДС продолжает прежний вопрос (`understand.test.ts`).
8. Числа в ответе о сумме только из `calcTax`; предохранитель действует и на ответы о сумме.
