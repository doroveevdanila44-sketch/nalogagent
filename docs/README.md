# Агент по НДС: пакет для Claude Code

Автор: Д.Дорофеев. Версия пакета: 1.0, 10.10.2026.

Это задание на реализацию приложения (PWA) для клиента ЛюксАвто41. Всё, что нужно для старта, лежит в этой папке. Положите её в корень нового репозитория как `docs/` и запускайте Claude Code из корня репозитория.

## Что строим

Закрытое приложение с входом по логину и PIN. После входа три вкладки:

1. **Агент**: чат с ИИ, который отвечает на вопросы про НДС, ставки и пороги. Числа даёт калькулятор на коде, модель только разбирает вопрос и объясняет результат.
2. **Дашборд**: группа юрлиц, предупреждения по порогам, график выручки, по каждому юрлицу три ставки (5, 7, 22). Выбранная ставка зелёная, две остальные красные для сравнения, налог тикает в реальном времени.
3. **Документы**: каталог шаблонов (договоры, допсоглашения, отчёты, проекты деклараций), заполнение из реквизитов юрлица и расчёта, документ как файл `.docx` или `.xlsx` (кнопки «Открыть» и «Отправить»), версии, комментарии, согласование. Шаблоны образцы, юристом не проверены.
4. **Обучение**: тур из шести шагов после первого входа и по кнопке «Пересмотреть обучение» в меню.

Работает на компьютере, планшете и телефоне, устанавливается на экран как приложение.

## Этапы

| Этап | Где работает | Данные | Языковой слой |
|---|---|---|---|
| Демо | Vercel + Neon Postgres | Выдуманные | Заглушка на правилах |
| Финал | Yandex Cloud целиком | Реальные от клиента | GigaChat API |

Код с первого дня пишется так, чтобы переезд был сменой переменных окружения, а не переписыванием.

## Как вести работу

1. Прочитать `SPEC.md` целиком, затем файл по текущему этапу.
2. Идти по `PROMPTS.md` по порядку, этап за этапом. Каждый этап заканчивается проверкой, которая описана в промпте.
3. Если требование в документах противоречит прототипу, прав документ. Прототип показывает вид и поведение, но считает на float и хранит всё в браузере.
4. Если чего-то не хватает, не придумывать. Записать вопрос в `docs/OPEN_QUESTIONS.md` и продолжить с самым безопасным вариантом.

## Правила текстов

- В документах и интерфейсе не использовать длинные тире. Только дефис или запятая.
- Инициалы пишутся слитно, без пробела между ними: «В.В. Солодов», а не «В. В. Солодов».
- Интерфейс на русском, формат чисел `ru-RU`, минус настоящий «−», валюта «₽».

## Границы безопасности (коротко, подробно в SPEC.md и AUTH.md)

- Данные клиента не уходят в зарубежные API. В демо данные выдуманные, в финале только GigaChat и Yandex Cloud.
- PIN хранится только как хэш, администратор его видеть не может и не должен.
- Модель не считает. Число в ответе, которого нет в расчёте, значит ответ не уходит.
