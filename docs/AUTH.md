# Вход в приложение

Доступ к агенту и дашборду только после входа. Без входа доступна одна страница `/login`. Регистрации нет, пользователя создаёт владелец продукта (Д.Дорофеев).

## Требования заказчика, дословно по смыслу

1. Логин: `luxautoowner`, латиницей.
2. Пароль: любой, задаёт Д.Дорофеев. Правил сложности нет.
3. Первый вход: пароль клиенту отправляет Д.Дорофеев сам, вне приложения.
4. После первого входа приложение предлагает придумать PIN из 4 цифр. Дальше при каждом входе вводится только PIN, как в банковском приложении.
5. PIN администратор видеть не должен никогда.

## Модель

Две ступени доверия.

- **Пароль** подтверждает человека и «привязывает» устройство. Нужен при первом входе на устройстве, после сброса и если PIN заблокирован.
- **PIN** открывает приложение на уже привязанном устройстве. Нужен при каждом запуске и после простоя.

PIN принадлежит паре «пользователь + устройство». На другом устройстве PIN придумывается заново после входа по паролю.

## Сценарии

### 1. Первый вход на устройстве

1. Экран `/login`: поля «Логин» и «Пароль», кнопка «Войти».
2. Сервер проверяет логин и пароль. Логин сравнивается без учёта регистра, пробелы по краям убираются.
3. При успехе создаётся запись устройства, в браузер ставится cookie устройства.
4. Приложение показывает экран «Придумайте PIN из 4 цифр», затем «Повторите PIN». Пропустить нельзя.
5. PIN сохраняется (только хэш), создаётся сессия, открывается вкладка «Агент».

### 2. Повторный вход

1. Приложение открыто после закрытия или после простоя. Cookie устройства есть.
2. Экран PIN: заголовок «Введите PIN», 4 точки, цифровая клавиатура 3 на 4 с кнопкой удаления. Ввод после четвёртой цифры отправляется сам.
3. Верный PIN открывает приложение. Неверный: точки трясутся, сообщение «Неверный PIN. Осталось попыток: N», счётчик на сервере.
4. Справа внизу одна кнопка, как на iPhone: «Отмена», пока не введено ни одной цифры, затем «Удалить» (стирает одну последнюю цифру). «Отмена» возвращает на экран пароля, то есть на сценарий 1 (PIN при этом не меняется, если не был заблокирован). Слева внизу пусто; «Войти по паролю» появляется там только при блокировке PIN (сценарий 3).

### 3. Блокировка

- 5 неверных PIN подряд на устройстве: PIN устройства блокируется. Экран PIN остаётся с сообщением «PIN заблокирован. Войдите по паролю», клавиши неактивны, слева внизу появляется «Войти по паролю». После входа по паролю PIN придумывается заново.
- 5 неверных паролей подряд на логине: блокировка входа на 15 минут, затем на 1 час, затем на 24 часа (удвоение). Ответ при блокировке всегда общий: «Слишком много попыток. Повторите позже».
- Сообщения об ошибке логина и пароля одинаковые: «Неверный логин или пароль». Не раскрывать, что именно неверно.

### 4. Простой и выход

- Блокировка на PIN после **5 минут** без активности, при сворачивании приложения на **1 минуту** и более, при закрытии вкладки. Значения в настройках окружения: `PIN_IDLE_MINUTES=5`, `PIN_BACKGROUND_SECONDS=60`.
- При блокировке на PIN данные на экране скрываются (экран PIN поверх), сессия на сервере остаётся, но API отвечает 401 до ввода PIN.
- Кнопка «Выйти» в настройках: удаляет сессию и cookie устройства, PIN устройства стирается.

### 5. Сброс

Забытый пароль или PIN: владелец продукта выполняет сброс командой (см. ниже). Сброс пароля завершает все сессии и стирает PIN на всех устройствах. Самообслуживания нет, письма и SMS не отправляются.

## Хранение секретов

| Что | Как хранится |
|---|---|
| Пароль | argon2id, соль внутри хэша, параметры не ниже рекомендаций OWASP. Библиотека `@node-rs/argon2`, запасной вариант `bcryptjs` со стоимостью не ниже 12 |
| PIN | argon2id от строки `userId:deviceId:PIN` плюс серверный секрет `PIN_PEPPER` из окружения. В базе только хэш |
| Токен сессии | 32 случайных байта, в cookie открытый токен, в базе его SHA-256 |
| Токен устройства | то же правило |

Требования, которые проверяются тестом:

- В базе, логах, ответах API, ошибках, трассировках и аналитике нет открытого пароля и PIN. В логах тела запросов к `/api/auth/*` не пишутся вообще.
- Нет страницы, команды или запроса, которые показывают PIN или хэш PIN. У администратора есть только команда сброса.
- Пароль и PIN не попадают в URL, в `localStorage` и в историю браузера.
- Поле PIN: `inputmode="numeric"`, `autocomplete="one-time-code"` отключён от менеджеров паролей, `type="password"` для маскировки, если используется ввод с клавиатуры.

## Cookies и сессии

- `pva_device`: идентификатор и секрет устройства. `HttpOnly; Secure; SameSite=Lax; Path=/`, срок 180 дней, продлевается при использовании.
- `pva_session`: сессия. `HttpOnly; Secure; SameSite=Lax; Path=/`, без срока (сессионная) плюс срок на сервере 12 часов с момента последнего ввода PIN.
- В локальной разработке `Secure` отключается только при `NODE_ENV=development`.
- Все запросы, меняющие состояние, проверяют `Origin` и CSRF-токен или используют `SameSite=Strict` для сессии. Выбрать один механизм и описать в коде.
- Все страницы, кроме `/login`, `/manifest.webmanifest`, статических файлов и иконок, закрыты middleware. Без сессии: редирект на `/login`, для API ответ 401.

## Эндпоинты

| Метод и путь | Назначение |
|---|---|
| `POST /api/auth/login` | Логин и пароль. Успех: cookie устройства, ответ `{needPinSetup:true}` или `{needPin:true}` |
| `POST /api/auth/pin/setup` | Первый PIN устройства (после входа по паролю). Тело `{pin}` |
| `POST /api/auth/pin` | Проверка PIN. Успех: cookie сессии |
| `POST /api/auth/lock` | Принудительная блокировка (клиент вызывает при простое) |
| `POST /api/auth/logout` | Выход |
| `GET /api/auth/state` | Состояние для клиента: `anonymous`, `needPinSetup`, `locked`, `ok` |

Валидация тела: `pin` строго `^\d{4}$`, логин до 64 символов, пароль до 256. Лимиты по IP и по логину в таблице `auth_events`, а не в памяти процесса (на Vercel процессы короткие).

## Запрещённые PIN

Не принимать при создании: `0000`, `1111`, `2222`, `3333`, `4444`, `5555`, `6666`, `7777`, `8888`, `9999`, `1234`, `4321`. Сообщение: «Выберите менее очевидный PIN».

## Команды владельца

Реализовать как скрипты в `scripts/`, запуск через `npm run`. Запрос пароля интерактивный, пароль в аргументы командной строки не передаётся (не попадает в историю оболочки).

| Команда | Что делает |
|---|---|
| `npm run user:create` | Создаёт пользователя `luxautoowner`. Спрашивает пароль дважды, выводит только «создан» |
| `npm run user:set-password` | Меняет пароль, завершает все сессии, стирает PIN всех устройств |
| `npm run user:revoke-devices` | Удаляет все устройства и сессии, пароль не меняется |

Начальный пароль клиенту отправляет Д.Дорофеев сам. Приложение пароль не показывает и никуда не отправляет.

## Экраны

Стиль общий с приложением (палитра, шрифт Onest, знак `luxauto41` в шапке живым текстом).

- **/login**: белый фон, по центру знак `luxauto41`, под ним две строки «Логин», «Пароль» (высота поля 44 px, радиус 12), кнопка на всю ширину цветом River Styx, текст белый. Ошибка красным под полями. Кнопка «показать пароль» глазом справа в поле пароля.
- **PIN-экран**: знак сверху, подпись, 4 точки (пустые: контур River Styx, заполненные: Tanned Wood), клавиатура 3 на 4, круглые кнопки 64 px, цифры Onest 500 24 px, нажатие подсвечивает Amber Autumn. Внизу справа «Отмена» или «Удалить», слева пусто (при блокировке PIN слева «Войти по паролю»). Экран на весь вид, без нижней панели.
- Меню «Настройки» не нужно в первой версии. Достаточно иконки замка в правом верхнем углу шапки: нажатие сразу блокирует на PIN. «Выйти» и «Сменить PIN» в маленьком листе по долгому нажатию или по второй иконке, на усмотрение, но обязательно доступны.

## Что отложено

- Вход по биометрии (WebAuthn, Face ID и отпечаток) как замена PIN. Подготовить таблицу, но не включать.
- Несколько пользователей и роли. В схеме поле `role` уже есть, значение одно: `owner`.
- Двухфакторный вход по коду.

## Тесты

1. Верный вход, неверный пароль, регистр логина.
2. Создание PIN, запрещённые PIN, повтор не совпал.
3. Пять неверных PIN: блокировка, вход по паролю снимает блокировку и требует новый PIN.
4. Пять неверных паролей: блокировка с удвоением.
5. Простой: API после блокировки отвечает 401.
6. Утечки: поиск по базе, логам и ответам не находит открытый пароль и PIN (тест с «ловушкой»: подставить заметный PIN, прогнать сценарий, искать строку).
7. Сброс пароля обнуляет сессии и PIN.
